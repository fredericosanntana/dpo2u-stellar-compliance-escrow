## Capture 2 (current `proof-response.bin` and `pi.hex`)

The first capture's request was deleted (it held the owner secret), so the statement was taken from a
second capture made the same way: a new disposable snapshot and pepper (issued_at 1795484369), one PASS
evaluate (status 1, reason 0) on the same gate, tx hash
`96f14586a855fb483c9757bc4f013a2093dfb8535d22f4edb24328e3671f267e` (identifier `006c7864…dbdc8`),
preview block 244701, 0.245 DUST. The `evaluateTransfer` call was again `POST /prove` (request
197,209,391 bytes, response 5,772 bytes).

`pi.hex` was produced offline (`--network none`) by `tools/midnight-export` at `f3d41d0`
(feat/fase-3-travel-rule-gate, rustc 1.95.0):
`midnight-export statement <request> <proof-response.bin> pi.hex` with `MIDNIGHT_PARAMS_DIR` holding
the public `bls_midnight_2p17`. It reported `request tag: (proof-preimage-versioned,option(proving-data),option(fr-bls))`
and `captured proof verifies; wrote 417 statement values`. The `.verifier`, `.bzkir` and `.zkir` are
unchanged (same gate, same build).

Before publishing, `pi.hex` was checked against the preview owner secret and this capture's pepper,
without printing either: raw bytes and every 8-byte fragment (both byte orders), hex text, the value as a
field element (mod r and the 31 + 1 byte split that the preimage uses for `Bytes<32>`) and 64-value bit
runs. No match for either. The request was deleted after the check.

## Why the request (ProofPreimage) is not here

The preimage carries every private witness of `evaluateTransfer`. Besides the fictitious transfer
data and the snapshot pepper, that includes `owner_secret()` (the circuit starts with
`assert_owner()`), and in this capture the owner secret of the preview contracts was found in it.
Publishing it would hand ownership of those contracts to anyone, so the request is withheld. A
publishable preimage needs a capture against a gate whose owner key is disposable too.

The sanctions snapshot and pepper used for this capture are fictitious, were created only for it and
are used nowhere else (the pepper is also a witness in the preimage). No real personal data is
involved anywhere.
