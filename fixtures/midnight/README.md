## Capture

A local proxy sat between the dpo2u-midnight CLI (`scripts/travel-rule-v10.ts evaluate`) and the
proof-server (`midnightntwrk/proof-server:9.0.1`) and saved every POST body and response. One PASS
evaluate (status 1, reason 0, tx identifier `007fb2a2…a8e4`, preview block 244492) made five calls:

| # | Route | Request bytes | Response bytes | Note |
| --- | --- | --- | --- | --- |
| 01 | `POST /check` | 1,616 | 49 | |
| 02 | `POST /prove` | 228,043 | 3,852 | another circuit of the same transaction |
| 03 | `POST /check` | 37,645 | 138 | |
| 04 | `POST /prove` | 197,209,348 | 5,772 | **`evaluateTransfer`**: `proof-response.bin` is this response |
| 05 | `POST /prove` | 2,032 | 2,940 | another circuit of the same transaction |

Layout of request 04: the `evaluateTransfer.prover` file is embedded verbatim at byte offset 5386,
followed by the `.verifier` at offset 197,174,722 and the ZKIR material at the end. With the prover
removed the request is 40,014 bytes (sha256 `275dcd84e5e34f409a0f02a961ad907e5889735b0b12d0538fff678a2d827afa`);
inserting the prover at offset 5386 rebuilds the original request (sha256
`61b2159019c4e3cba2b36f4278f00cf05be3ee19922edefe1b5f1b472a4d92f4`) byte for byte.

## Why the request (ProofPreimage) is not here

The preimage carries every private witness of `evaluateTransfer`. Besides the fictitious transfer
data and the snapshot pepper, that includes `owner_secret()` (the circuit starts with
`assert_owner()`), and in this capture the owner secret of the preview contracts was found in it.
Publishing it would hand ownership of those contracts to anyone, so the request is withheld. A
publishable preimage needs a capture against a gate whose owner key is disposable too.

The sanctions snapshot and pepper used for this capture are fictitious, were created only for it and
are used nowhere else (the pepper is also a witness in the preimage). No real personal data is
involved anywhere.
